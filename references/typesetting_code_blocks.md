# 代码排版与注释规范

本文档定义 Microsoft Word 环境下代码框流式跨页、超长逻辑行折行缩进及注释对齐的工程准则。

---

## 一、 流式跨页

长代码段在传统排版中易导致上一页底部大面积空白。本模块采用流式跨页控制：

1. **表格行允许跨页切分**：
   - 1×1 代码框表格行严禁添加 `<w:cantSplit/>` 属性；
   - 当当前页底部空间不足以容纳全部代码时，允许剩余代码自然切分并流向下一页顶端。
2. **段落切页约束**：
   - 代码框内部除前 1～2 行外，其余代码行严禁设置 `keep_with_next = True`；
   - 仅依靠上方代码说明段落与代码框首行的软连接防止头部孤悬。

---

## 二、 代码容量与折行控制

### 1. 单行容量上限（68 字符限制）
在基准宽度 $8523\text{ dxa}$ 下，扣除单元格内边距后净宽度为 $8323\text{ dxa}$。Consolas $11\text{ pt}$ 字宽约为 $121\text{ dxa}$：
- 单行最大安全容量为 $68$ 字符；
- **单行完整性**：总长度 $\le 68$ 字符的代码行，必须保持在单行完整展示，严禁过早截断。

### 2. 逻辑单行跨行折行与内在缩进
许多代码在语义上属于以分号结尾的逻辑单行（例如超长 `printf` 调用、复合布尔判断或数组声明），但字符总数超出 Word 单行容量。此时必须在折行时展现代码内在的层次结构：
1. **结构表现形式**：
   - 在 Word 中作为一个完整段落维护，折行处使用软换行符（`\x0b` / Shift+Enter）；
   - 段落设置**挂起缩进（Hanging Indent）**，即首行缩进小于零、后续行缩进大于零（例如首行缩进 $-47.3\text{ pt}$，左缩进 $71.4\text{ pt}$，使后续行净缩进比首行深 8 字符）；
2. **语义缩进对齐**：
   - **函数调用（如 `printf`）**：第一行展示函数名及首个参数（至首个左括号 `(` 之后）；第二行至分号结尾的所有续行，统一向右深缩进并对齐在括号内侧参数位置；
   - **数组或结构体声明**：续行对齐在大括号 `{` 内侧；
   - **复合布尔条件（`if`）**：续行对齐在外层条件括号内部；
3. **视觉效果**：
   续行绝不平铺或仅做简单的 4 格缩进，而是通过深缩进明确表达“本行是上一主干语句参数的内在延续”。

## 三、 注释对齐

代码框内注释分为两类处理：

### 1. 行尾跟随注释（Trailing Comments）
- **定义**：紧随在可执行代码语句后的解释性注释（`statement; // comment`）。
- **对齐原则**：**同一代码块内，所有行尾注释的双斜杠 `//` 在垂直方向上必须严格对齐成一条直线**。
- **自适应基准列计算**：
  - 不强制绑定某一个绝对列数，而是自适应计算；
  - 统计当前代码块内所有带注释行的纯代码长度 $L_i$，设最大长度为 $L_{\text{max}} = \max(L_i)$；
  - 对齐列设为：
    $$Col_{\text{align}} = \max(L_{\text{max}} + \Delta, \text{DefaultCol})\quad (\Delta \ge 2\sim 4\text{ 空格})$$
  - 若代码普遍偏短，可对齐至舒适基准列（如第 44 列）；若代码本身较长，则整块注释整体右移后推对齐。
  - 严禁机械将 `//` 前空格压缩为 2 格。

### 2. 独立单行长注释（Full-line Comments）
- **定义**：整行纯为注释、用于引导后续步骤的独立句子（`// 核心算法逻辑：...`）。
- **处理原则**：**严禁参与右侧列对齐**。独立单行长注释保持顶格或跟随当前作用域层级缩进（0~2 字符），清晰交代后续逻辑。
