# Word 实验报告紧凑排版工程规范（可选插件）

> 本规范定义了中文理工科实验报告在 Microsoft Word（`.docx` / `.doc`）环境下的排版工程准则。
> 本模块作为独立可选插件存在，**默认不启用**。仅当用户显式要求排版或在询问中明确确认后方可激活。
> **工程核心原则：公式与数字 > 自然语言。所有版面尺寸、空行状态、字符容量、对齐列偏移量均具有硬性数值约束。**

---

## 一、 交互与激活契约

1. **显式询问原则**：
   Agent 在接收到实验报告撰写或润色任务时，若用户未明确提出排版需求，必须用自然语言显式询问：
   > *“文稿语言审改已准备就绪。请问本次是否需要启用【Word 紧凑排版模块】（负责 8523 dxa 居中基准、空行三态法则、代码框跨页流式布局、Beautifier 注释垂直对齐、大章节强制分页、西文双轨字体及 OMML 原生公式处理）？若不需要，将默认仅对文稿进行语言与逻辑审查。”*
2. **保守默认**：
   若用户未作明确指定、未明确确认或回复不需要，**默认坚决不启用排版模块**，全流程保持原有的纯文本/Markdown 语言审改。
3. **两阶段执行**：
   当用户确认开启排版时，排版流程作为后置渲染器运行：必须在语言文字与逻辑审改通过（或初稿生成）后，再将文稿注入 Word 模板并应用本规范。

## 二、 容器尺寸与收窄居中基准（8523 dxa 几何法则）

传统 Word 排版常直接将表格和代码框拉伸至 $100\%$ 正文版心宽度，导致版面呆板且缺乏内嵌容器感。本规范建立严格的收窄居中几何基准：

### 1. 页面版心几何参数（A4 标准）
- 页面宽度：$W_{\text{page}} = 11906\text{ dxa}$（$210.0\text{ mm}$）
- 页面高度：$H_{\text{page}} = 16838\text{ dxa}$（$297.0\text{ mm}$）
- 左边距：$M_{\text{left}} = 1418\text{ dxa}$（$25.0\text{ mm}$）；右边距：$M_{\text{right}} = 1361\text{ dxa}$（$24.0\text{ mm}$）
- 正文版心宽度：
  $$W_{\text{body}} = W_{\text{page}} - M_{\text{left}} - M_{\text{right}} = 9127\text{ dxa} \approx 161.0\text{ mm} \approx 456.4\text{ pt}$$

### 2. 表格与代码框收窄定死参数
- **基准总宽**：**定死 $W_{\text{box}} = 8523\text{ dxa} \approx 150.3\text{ mm} \approx 426.15\text{ pt}$**
  - 版心占比：$\frac{W_{\text{box}}}{W_{\text{body}}} = \frac{8523}{9127} \approx 93.38\%$
  - 两侧呼吸内缩量（水平留白）：
    $$\Delta W_{\text{pad}} = \frac{W_{\text{body}} - W_{\text{box}}}{2} = \frac{9127 - 8523}{2} = 302\text{ dxa} \approx 5.33\text{ mm} \approx 15.1\text{ pt}$$
- **水平对齐**：必须显式设置 `<w:jc w:val="center"/>`（居中对齐）。
- **作用对象**：
  - **多列数据统计表格**：总宽定死为 $8523\text{ dxa}$（`w:tblW[@w="8523"][@type="dxa"]`），各列宽之和满足 $\sum w_i = 8523\text{ dxa}$；
  - **1×1 代码框 / 终端输出框**：总宽与单元格宽**同样定死为 $8523\text{ dxa}$**（`w:tblW[@w="8523"]`，`w:tcW[@w="8523"]`），严禁使用 $9099\text{ dxa}$ 或贴满 $9128\text{ dxa}$。
- **单元格内边距与边框**：
  - 单元格内边距：上下 $80\text{ dxa}$（$4\text{ pt}$），左右 $100\text{ dxa}$（$5\text{ pt}$）；
  - 边框：$0.5\text{ pt}$ 单实线（`w:sz="4"` 或 `"5"`），颜色统一为浅灰 `#D9D9D9`。

## 三、 结构与大章节分页控制（Page Break Before）

报告中的核心模块与一级大标题，必须保持视觉独立与清晰划分，严禁在上一章节末尾页脚孤悬：

1. **核心一级大标题分页硬约束**：
   - 匹配模式：`^[一二三四五六七八九十]+、`（例如“一、回答问题”、“二、实验详细设计”、“三、测试与验证”等）；
   - **必须强制另起新页**：段落属性必须设置 `<w:pageBreakBefore/>`（或前置插入 `<w:br w:type="page"/>`）；
   - 杜绝核心一级标题被挤压在上一部分结尾的页脚底部，确保每个核心大章节从崭新一页顶端展开。
2. **标题与层次防孤行（Keep with Next）**：
   - 报告中所有各级标题（大标题、小标题、题干段落）必须统一设置 `keep_with_next = True`（`<w:keepNext/>`），确保标题与紧随的正文首段绑定在同一页。

## 四、 空间节奏：空行三态法则（Space Rhythm）

排版紧凑与呼吸感的核心在于对象前后的空行控制，严格遵循三态法则：

1. **代码框（1×1 单格表格）**：**上不空行、下空一行**
   - **上不空行**：引导语（如“相关核心代码如下：”）段落与代码框紧贴，中间严禁插入空段落；且引导语段落必须设置 `keep_with_next = True`，防止代码框被分页拆分到下一页而导致引导语在页末孤悬。
   - **下空一行**：紧接在代码框表格之后，必须单独插入一个 $11\text{ pt}$ 的独立空行段落（Spacer），再接后续正文或下一小节，形成明确的层次隔离。
2. **数据统计表（多行多列统计/参数表格）**：**上空一行、下空一行**
   - 表格上方空一行（$11\text{ pt}$ Spacer）、下方空一行（$11\text{ pt}$ Spacer），使其作为独立数据容器嵌入文本流。
3. **图表与截图（Figure / Inline Drawing）**：**上空一行、下空一行**
   - 图片及其图题说明段落上方空一行、下方空一行，避免图像与上下行正文发生拥挤粘连。

## 五、 代码框流式跨页与折行容量（No Unnecessary Wrap）

### 1. 跨页流式布局硬性约束（Compact Streaming Rule）
长代码段在传统排版中极易导致“上一页下半部大面积死白（留白高达半页）”的恶劣视觉问题。本模块通过流式跨页彻底解决该痛点：
- **严禁对代码框整体设置防拆分**：1×1 代码表格行绝对严禁添加 `<w:cantSplit/>` 属性；必须允许 Word 在当前页底部容纳不下整框代码时，自然将剩余代码切分流到下一页顶端。
- **代码行间允许自然切页**：代码框内部除前 1～2 行外，其余代码段落**严禁设置** `keep_with_next = True`；允许代码在任意逻辑语句行之间平滑跨页，吃透并填满当前页底部的剩余空间。
- **防头悬挂（Head Protection）**：仅由代码框上方引导语的 `keep_with_next = True` 与代码框第 1～2 行绑定，保证绝不会出现引导语留在一页最后一行而代码框整块跳到下页。

### 2. 代码单行容量极限与严禁非必要换行
在基准宽度 $8523\text{ dxa}$ 与 Consolas $11\text{ pt}$（字符字宽约 $121\text{ dxa} \approx 6.05\text{ pt}$）下，扣除单元格内边距（$200\text{ dxa}$）后的净可用宽度为 $8323\text{ dxa}$：
- **单行安全字符容量**：
  $$C_{\text{max}} = \left\lfloor \frac{8323\text{ dxa}}{121\text{ dxa/char}} \right\rfloor = 68\text{ 字符}$$
- **严禁非必要折行**：
  - 代码行总长度 $\le 68$ 字符时，**绝对严禁折行**；
  - 严禁机械设置 50~58 字符的过早折行阈值；
  - 诸如 `vmprint_walk((pagetable_t)PTE2PA(pte), level + 1, (prefix << 9) | i);` 或 `if ((pte & PTE_V) && (pte & (PTE_R | PTE_W | PTE_X)) == 0) {` 等单行语句（$\le 68$ 字符），**必须保持单行完整展示**，杜绝碎裂为多行并产生多余的续行悬挂空格；
  - 仅当单行真实长度 $> 68$ 字符时，方允许在逗号或操作符后自然换行，续行缩进 4 格。

## 六、 代码注释规范：VS Code Beautifier 风格垂直对齐与长注释顶格

在代码框内，注释严格区分两大类并遵循精确列偏移对齐：

### 1. 行尾注释（Trailing Comments）：垂直列对齐
- **适用场景**：紧跟在有效代码语句后的解释性注释（如 `w_satp(...); // ...`）。
- **基准对齐列**：
  - 设该代码块中所有带行尾注释的纯代码部分长度为 $L_{\text{code}}$，其最大长度为 $L_{\text{max}} = \max(L_{\text{code}})$；
  - **默认基准对齐列定死为第 44 列**（即第 45 字符位置，从 0 计数为 44）；
  - 若代码较长导致 $L_{\text{max}} + 4 > 44$，则对齐列自适应调整为：
    $$Col_{\text{align}} = \min(68 - \max(\text{len}(\text{comment})), \max(L_{\text{max}} + 4, 44))$$
  - 在纯代码末尾与 `//` 之间填充数量为 $Col_{\text{align}} - L_{\text{code}}$ 的空格，**确保该代码块内所有行尾注释的 `//` 在垂直方向呈现如 VS Code Beautifier 插件般的绝对列对齐**。
- **严禁行为**：严禁粗暴将 `//` 前空格压缩为 2 格（`  //`），破坏对齐美感。

### 2. 独立单行长注释（Full-line Comments）：顶格 / 紧跟缩进
- **适用场景**：整行纯为注释、用于引导后续逻辑段落的长句（如 `// 当前表的所有项处理完成后，只回收页表页。`）。
- **硬性约束**：**严禁参与右侧列对齐**！独立长注释应紧贴当前代码块的作用域缩进（顶格或缩进 0~2 格），直接清晰陈述逻辑步骤。

## 七、 字体规范：西文字符“双轨分工”

报告正文中文字体统一为宋体（正文 $11\text{ pt}$，小标题 $13\text{ pt}$，大标题 $15\text{ pt}$）。西文字符严格区分双轨：

1. **代码与标识符轨（Consolas $11\text{ pt}$）**：
   - 仅用于源代码、函数名（如 `cudaMemcpy`、`vmprint_walk`、`bget`）、变量（`b->refcnt`、`pte`）、文件名（`vm.c`）、系统调用及代码框内的全文。
2. **散文与缩写轨（Times New Roman $11\text{ pt}$）**：
   - 用于通用硬件与体系结构英文缩写（$\text{GPU}$、$\text{CPU}$、$\text{RAM}$、$\text{LRU}$、$\text{PTE}$、$\text{Sv39}$ 等）、纯英文散文单词、阿拉伯数字、以及句末英文半角句点 `.`。
   - **红线警告**：严禁将 $\text{GPU}$、$\text{CPU}$、$\text{RAM}$ 等通用缩写误设为 Consolas 等宽字体！

## 八、 数学与参数：Word 原生公式化（OMML）

1. **拒绝伪文本公式**：
   - 严禁使用普通文本硬拼或自然语言冗长叙述参数（如写成“矩阵边长为512”或“A=B+8i”或“h=(blockno+dev)%31”）；
   - 必须转换为 Word 原生数学对象（OMML `m:oMath`），生成专业矢量公式。
2. **公式语义规范**：
   - 单字母变量使用数学斜体（如 $A$、$B$、$h$、$b$、$N$、$i$）；
   - 多字母标识符、函数名、运算符号与数字使用直立体（如 $\text{blockno}$、$\text{dev}$、$\bmod$、$31$、$512$、$4\text{ KB}$）；
   - 矩阵维度与容量：$32 \times 32$、$4\text{ KB}$；变量等式与关系式：$N = 512 = 2^9$、$A = B + 8i$。
